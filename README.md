#  Servicing Decision Science — Repeat-Contact Prediction & Customer Segmentation

**Portfolio project prepared for:** *Analyst – Data Science, Global Servicing
Decision Science (GSDS), American Express*

> **One-liner:** An end-to-end decision-science project on servicing
> interactions — **SQL** builds the model-ready dataset, **Python** runs EDA
> and trains foundational **ML models** (classification, regression,
> tree-based, clustering) plus a **neural network**, and a written
> **findings report** translates everything into operational insight.

##  Results at a glance

**Dataset:** 6,000 servicing interactions · 2,000 customers · 120 agents ·
12 months · Phone / Chat / Email across Payments, Billing, Technical,
Account Management. Repeat-contact rate: **25.9%**.

### Repeat-contact classification (test n = 1,500)

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| **Logistic Regression** | 0.721 | 0.474 | **0.717** | **0.570** | **0.780** |
| Random Forest | 0.759 | 0.532 | 0.585 | 0.557 | 0.768 |
| Decision Tree | 0.720 | 0.468 | 0.606 | 0.528 | 0.684 |
| Neural Network (MLP) | 0.703 | 0.429 | 0.446 | 0.437 | 0.677 |

### Handle-time regression (test n = 1,500)

| Model | RMSE (min) | MAE (min) | R² |
|---|---|---|---|
| **Linear Regression** | **2.55** | 2.01 | **0.761** |
| Random Forest Regressor | 2.71 | 2.14 | 0.731 |

### Customer segmentation (K-Means, k = 4, n = 1,678 customers)

| Cluster | Customers | Profile (avg) |
|---|---|---|
| 0 | 381 (22.7%) | Long handle times (18.5 min), low FCR (51%), high severity (3.2) — **high-friction** |
| 1 | 524 (31.2%) | Phone-heavy (81%), easy issues (sev 1.9), high FCR (77%) — **routine phone** |
| 2 | 449 (26.8%) | Digital channels (20% phone), fast (12.0 min), high FCR (72%) — **digital-first** |
| 3 | 324 (19.3%) | Very high contact frequency (8.0 interactions) — **high-frequency** |


Pipeline: generate data → build SQLite & run SQL → EDA → train models →
clustering → findings report.

##  Key insights (from the findings report)

1. **First-contact resolution is the #1 lever** — repeat rate drops from
   **42.4%** (not resolved) to **18.2%** (resolved) (chi-square p ≈ 1e-87).
2. **Billing & Payments carry the most repeat risk** (highest repeat rates
   by department).
3. A **ranked at-risk list is feasible** — best model ROC-AUC **0.780**,
   recall **0.72**: good enough to prioritise proactive follow-ups.
4. **Handle time is forecastable** (RMSE **2.55 min**, R² **0.76**) —
   supports workforce planning.
5. **Four customer segments** give operations a simple lens on where repeat
   work concentrates.

##  Data dictionary (interactions)

| Column | Meaning |
|---|---|
| `channel` | Phone / Chat / Email |
| `department` | Payments / Billing / Technical / Account Management |
| `issue_category` | Specific issue within the department |
| `severity` | 1 (low) – 5 (critical) |
| `handle_time_min` | Agent handle time in minutes |
| `first_contact_resolution` | 1 if resolved on first contact |
| `satisfaction_score` | 1–5 post-interaction score (~10% missing) |
| `prior_contacts_90d` | Customer's contacts in the trailing 90 days (**computed in SQL**) |
| `repeat_contact_30d` | **Target** — customer contacted again within 30 days |

##  Reproducibility & disclaimer

- Fully reproducible: fixed seed (42); `python run_all.py` regenerates data,
  models, charts and the report from scratch.
- Data is **synthetic** (behaviourally realistic, seeded). Replace
  `data/*.csv` with real servicing extracts (same schema) to reuse the
  pipeline unchanged — the SQL scripts are standard SQL and port to
  SQL Server / PostgreSQL / BigQuery with minor dialect tweaks.
- Prepared as a job-application portfolio project.
